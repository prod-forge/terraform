# Client VPN CA private key is kept in Terraform state

- **What:** the Client VPN client root certificate is imported into ACM together with the CA private key, so the CA key is stored in the Terraform state (and in ACM). Anyone who can read the state can sign new client certificates for the VPN.
- **Where:** `infrastructure/modules/stack/main.tf` (`module "client_vpn_certificate"`, `private_key = var.vpn_ca_private_key`), `infrastructure/modules/vpn/certificates/client/main.tf` (`aws_acm_certificate.vpn_client`), the `vpn_ca_private_key` input of the environment roots; the certificates are created as in `guide/debugging.md` (server and client certificates signed by the same `ca.key`).
- **Why deferred:** the owner decided on 2026-11-05 not to change the VPN infrastructure now; the endpoint runs in prod only (`enable_client_vpn`), and replacing the client root certificate ARN changes the live endpoint.
- **What a fix needs:** because the client certificates are signed by the same CA as the server certificate, the endpoint can use the server certificate ARN as `root_certificate_chain_arn` (AWS Client VPN mutual authentication). Point `authentication_options.root_certificate_chain_arn` at `module.server_vpn_certificate[0].arn`, remove `module.client_vpn_certificate`, its module and the `vpn_ca_private_key` input, update `guide/debugging.md`, and plan it against prod first: the endpoint authentication change may replace the endpoint and disconnect clients. Only the server key then stays in state.
